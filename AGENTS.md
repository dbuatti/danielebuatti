# Comms and social workspace rules

This workspace is the home of Daniele Buatti's comms and social work.

Voice, accounts and the brand live in the shared brain: `~/Projects/comms/docs/voice.md`, `docs/channels.md`, `docs/rates.md`. This file keeps only the safety-critical rules.

## Read first

1. `~/systems-repo/INDEX.md` and `~/systems-repo/STATUS.md`
2. `~/systems-repo/systems/comms-social/README.md`, the master brief
3. `~/Piano by Heart/COMMS_BRIEF.md`, the PBH playbook, for any Piano by Heart work
4. `~/dyad-apps/resonance-with-daniele/emails/README.md` for email work

The consolidated OpenChamber root for all of this is `~/Projects/comms/`. It links to every folder above plus when-free and the kinesiology app.

## Non negotiables

- Draft, then wait for Daniele's explicit approval. Never publish, post, send or schedule anything without a green light.
- No em dashes, ever, in anything. Use commas and periods. This applies to captions, subjects, replies, event copy, briefs and these files.
- Keep both briefs current. When a fact changes, edit them in place. Dated numbers stay dated.
- Verify date, time, venue, price and link against the live source before putting them in copy. Never invent them.
- One Resonance per post: @resonance.choir.melb is the choir, @resonance.with.daniele is body work. Default everything else to @daniele.buatti.
- Piano by Heart: "tea to close", never "tea on arrival". The piano runs about an hour, then tea. 5:00 to 6:30pm covers both.
- Voice, tone and sign-off: see `~/Projects/comms/docs/voice.md`.

## Workflow

- Write drafts to `drafts/` in this workspace, never straight into a live platform.
- Use `/checkin` for the periodic summary.
- Ask the `brand-guardian` subagent to review every draft before showing it to Daniele.

## New systems

If you create a script, daemon, launch agent, port, route or deployment, add a row to `~/systems-repo/INDEX.md` and the matching file in `~/systems-repo/inventory/`.
